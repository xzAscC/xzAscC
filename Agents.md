# Agent Instructions

1. State each piece of information about a change only once. Do not repeat progress, implementation details, validation results, or summaries.

2. Follow Test-Driven Development (TDD): write a failing test first, implement the smallest change needed to make it pass, and then refactor while keeping all tests green.

3. When requirements are uncertain or ambiguous, ask detailed questions instead of making assumptions. Clarify the expected behavior, scope, constraints, and preferred approach before proceeding.

4. Make small, focused commits throughout the work rather than one large commit at the end. When finished, write a brief and clear pull request description that summarizes the changes and validation performed.
